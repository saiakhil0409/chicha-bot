BUG-01
"Save & Wake Chicha" button not working ✅ Fixed Auth
Clicking the setup button did nothing. No error shown. App never opened.
▼
What Happened
The login card expanded when "Set up your Groq API key" was clicked. Fields were filled with API key and password. Clicking "Save & Wake Chicha" produced no response — no error, no app opening, nothing. Silent failure.
Root Cause
Two separate causes found on investigation:

Cause 1 — Overflow hidden: body had overflow:hidden globally. When the setup form expanded the login card taller than the viewport, the button was physically below the visible area — present in the DOM but invisible and unclickable.

Cause 2 — App not defined: auth.js loads at line 367, app.js loads at line 377. doSetup() called App.launch() — but at click time, App was technically defined (all scripts load before any interaction). However an intermediate version used window.location.reload() which cleared sessionStorage, breaking the auth check on reload.
Changes Made
✗ Before — style.css
html, body {
  height: 100%;
  overflow: hidden; /* global — broke login */
}
✓ After — style.css
html, body { height: 100%; }
body { overflow-y: auto; }
body.app-open { overflow: hidden; }
✗ Before — auth.js
doSetup() {
  // ...encrypt key...
  window.location.reload(); // cleared sessionStorage!
}
✓ After — auth.js
doSetup() {
  // ...encrypt key...
  sessionStorage.setItem('chicha_pw', pw);
  App.launch(); // direct call, no reload
}
Outcome
✅ Fully fixed. Setup form now scrollable. App launches directly without page reload.
Lesson Learned
Never apply overflow:hidden globally. Login forms and modals need to scroll. Apply overflow:hidden only to the main app container via a body class (body.app-open), not to body universally. Always test forms at minimum viewport height.

BUG-03
Browser serving old JS despite new files uploaded ✅ Fixed Cache
Fixed bugs were not visible after upload. Browser kept running old broken code. Same errors appearing repeatedly.
▼
Root Cause
GitHub Pages CDN caches static assets aggressively. Scripts loaded as chat.js were served from cache regardless of file changes on GitHub. The browser never fetched the updated files. This caused fixes to appear not working when they had actually been applied correctly.
Changes Made
✗ Before — index.html
<script src="js/chat.js"></script>
<script src="js/app.js"></script>
✓ After — index.html (v=3)
<script src="js/chat.js?v=3"></script>
<script src="js/app.js?v=3"></script>
Outcome
✅ Fixed. Cache-bust query string forces browser to fetch fresh files. Currently on v=3.
Lesson Learned
Always increment cache-bust version when deploying fixes. Currently v=3. Next major update should go to v=4. When debugging, always test in Incognito window first — it has zero cache and shows true deployed state. If it works in Incognito but not normal browser, it's always a cache issue.
BUG-04
"Start Learning" teaching wrong concept — showed CREATE TABLE for "What is a Database" ✅ Fixed Learning Flow
Theory concept showed SQL syntax it shouldn't know about. Step 2 showed CREATE TABLE syntax when teaching "What is a Database".
▼
Root Cause
The teaching prompt had no separation between theory concepts (no SQL) and SQL command concepts. The AI associated "What is a Database" with databases → tables → CREATE TABLE and added syntax freely. Additionally, getSparkForTopic() was picking a random concept regardless of mastery order, so a zero-knowledge beginner could land on an advanced concept like "Window functions" as their first lesson.
Changes Made
✓ Fix 1 — Two separate teaching prompts in chat.js
const THEORY_CONCEPTS = ['What is a Database', 'What is a Table', 'Data types', ...];

const msg = isTheory(concept)
  ? `Teach ONLY: "${concept}" — THEORY, no SQL code.
     Step 1 — Analogy. Step 2 — Why it matters. Step 3 — Real world example.
     STRICT: No SQL. No code.`
  : `Teach ONLY: "${concept}" — SQL command.
     Step 1 — Analogy. Step 2 — Syntax. Step 3 — Example.`;
✓ Fix 2 — Curriculum order in getSparkForTopic()
function getSparkForTopic(topic, surpriseMode = false) {
  const unmastered = allConcepts.filter(c => !mastered.includes(c));
  // DEFAULT: always pick FIRST unmastered in curriculum order
  // SURPRISE: random from unmastered
  const concept = surpriseMode
    ? pool[Math.floor(Math.random() * pool.length)]
    : pool[0]; // ← always first unmastered
}
Outcome
✅ Fixed. Theory concepts show no SQL. Beginners always start at "What is a Database" → "What is a Table" → in curriculum order.
Lesson Learned
LLMs don't respect implicit boundaries — make them explicit. "What is a Database" teaching SQL is natural LLM behaviour — it associates the concepts. You need a hard explicit instruction: "THEORY — no SQL code" as a separate prompt, not a rule inside a shared prompt.
BUG-05
"Yes" triggering mastery — concept mastered after single "yes" answer ✅ Fixed Learning Flow
Typing "yes" after Chicha's teaching caused [CORRECT] to fire and mastery card to appear immediately. No practice question asked.
▼
Root Cause
The system prompt said "If the student gives a correct answer → say [CORRECT]". The AI interpreted "yes" (as in "yes, I'm ready") as a correct answer to an implicit question. The [CORRECT] signal fired, processSignals() incremented the mastery counter, and with threshold at 1, mastery triggered immediately.
Changes Made
✓ Fix — Explicit signal rules in system prompt
[CORRECT] = ONLY when student gives actual correct answer (SQL/MCQ)
          NOT for "yes/sure/ok/ready"

When student says yes/sure/ready/ok:
→ Ask ONE practice question. Do NOT say [CORRECT].
Outcome
✅ Fixed. "Yes" now triggers a practice question. [CORRECT] only fires on actual answers.
BUG-06
MCQ correct answer always option (c) ✅ Fixed AI / Prompt
Regardless of the question, the correct MCQ answer was almost always option (c). A student could guess (c) every time and get most answers right.
▼
Root Cause
llama-3.3-70b-versatile (the Groq model used) has a positional bias — when generating MCQs without position guidance, it defaults to placing the correct answer at option (c) approximately 60-70% of the time. This is a known pattern in instruction-tuned LLMs.
Changes Made
✓ Fix — Random position instruction in prompt
const randomPos = ['a','b','c','d'][Math.floor(Math.random()*4)];

// In system prompt:
`MCQ about "${concept}" at ${diff.level} difficulty.
Correct answer goes at position: ${randomPos}
Write ONLY:
Question: [question]
(a) [option]  (b) [option]
(c) [option]  (d) [option]`
Outcome
⚠️ Mostly fixed. Position instruction reduces (c) bias significantly. Not 100% reliable — model occasionally ignores the position instruction. Full fix requires structured JSON output (Phase 2 planned).
Lesson Learned
LLMs have statistical biases in generation. The real fix is structured output: generate MCQ as JSON {"question": "...", "options": [{"text": "...", "correct": true}]} and shuffle client-side. Then correct answer position is 100% random, guaranteed by code not by prompt instruction.
BUG-07
Concept drift — questions about topics not yet taught ⚠️ Partial Fix AI / Prompt
Teaching "What is a Table" → Chicha asked about primary keys, One-to-Many relationships, normalization. All are concepts 20+ positions ahead in the curriculum.
▼
Root Cause
LLMs naturally associate related concepts. "What is a Table" → the model connects tables to primary keys, foreign keys, relationships — things it knows are related. No prompt instruction fully prevents this because the model's training makes these associations deeply embedded.
Changes Made
✓ Fix — Curriculum position context in system prompt
CURRICULUM POSITION:
Taught so far: What is a Database
NOW teaching: "What is a Table" (2/49)
Not yet taught: Data types, CREATE DATABASE, CREATE TABLE...

CONCEPT BOUNDARY — STRICT:
Only ask about "${concept}".
Never reference items from "not yet taught".
FORBIDDEN: SQL syntax, relationships, keys, normalization.
Outcome
⚠️ Reduced but not eliminated. Explicit taught/not-taught context helps significantly. The model still occasionally drifts — especially on theory concepts where related SQL concepts are strongly associated in training. Full fix requires structured output with topic validation.
Future Fix
Structural solution (Phase 2): Chicha returns JSON with a topic_used field. Client validates it matches the current concept before displaying. If it drifts, client rejects and retries. This makes concept boundary enforcement reliable regardless of model behaviour.
BUG-08
[CORRECT] fires after 1 question instead of required threshold ⚠️ Partial Fix AI / Prompt
Concept mastered after answering 1 question correctly despite threshold being set to 5 for theory concepts.
▼
Root Cause
Three overlapping causes:

Cause 1: Chicha included [CORRECT] in her question-asking message (not just answer-evaluation). processSignals() detected it and incremented the counter before any answer was given.

Cause 2: Chicha's reply after [CORRECT] said "Ready for the next topic: What is a Table" — triggering the app to advance before the mastery threshold was reached.

Cause 3: Browser cache — user was seeing old code with a lower threshold.
Changes Made
✓ Fix 1 — Two-mode prompt (asking vs evaluating)
RULES:
1. When student says yes/ready → ask ONE question. Nothing else.
2. When student sends answer → evaluate it.
3. NEVER decide to move to next topic yourself.
4. After [CORRECT], just celebrate briefly. Stop.
✓ Fix 2 — Client-side reply sanitisation
function sanitiseReply(reply) {
  if (!reply.includes('[CORRECT]')) return reply;
  // Strip sentences mentioning next topic/step/concept
  return sentences.filter(s => !s.includes('next topic')
    && !s.includes('next step') && !s.includes('ready to proceed')
    && !s.includes('move on') ...).join(' ');
}
Outcome
⚠️ Mostly fixed. Two-mode prompt significantly reduces premature [CORRECT]. sanitiseReply() catches known "move on" phrases. Model occasionally uses unknown phrasings that bypass the filter. Full fix requires structured JSON output.
Future Fix
Root cause is free-text signal parsing. When we scan reply text for "[CORRECT]", any accidental inclusion triggers mastery. The fix: Chicha returns {"signal": "CORRECT", "message": "..."}. Signal comes from a dedicated JSON field, not from scanning free text. This is the single highest-impact fix planned for Phase 2.
BUG-09
Prompt instructions leaking into chat — "Do NOT include in this message" showing to user ✅ Fixed AI / Prompt
User saw raw system prompt text in the chat bubble: "Do NOT include in this message." and "⛔" symbols appearing in Chicha's responses.
▼
Root Cause
System prompt instructions were embedded adjacent to the output format template. When the AI fills in the format template, it includes surrounding text as context. Instructions like "Do NOT include [CORRECT] or [WRONG] when asking. Just ask." placed directly after the format block were echoed as part of the output.
Changes Made
✗ Before — adjacent to format
Format:
Question: [question]
(a) [option] (b) [option]
(c) [option] (d) [option]
⛔ Do NOT include [CORRECT]
or [WRONG] when asking.
✓ After — separated sections
QUESTION FORMAT (when asking):
Question: [question]
(a) [option] (b) [option]
(c) [option] (d) [option]

EVALUATION FORMAT (when answering):
Correct → write: [CORRECT]
Wrong → write: [WRONG]
Outcome
✅ Fixed. Separating instruction sections from output format templates prevents leakage.
Lesson Learned
Never put "do not say X" immediately adjacent to a format template. The model reads them together. Keep instructions in a separate section with a clear header, far from the output format. Meta-instructions about what NOT to include are especially prone to being echoed.
BUG-10
SVG table text invisible — dark text on dark background ✅ Fixed UI / Layout
The "What is a Table" visual diagram showed a table with empty-looking rows. Text was present but invisible.
▼
Root Cause
The tableRow() helper function in visualizer.js used fill:inherit for default (non-highlighted) row text. SVG does not inherit color from CSS the way HTML does — it falls back to black (#000000) which is invisible on the dark (#0a0a18) background.
Changes Made
✗ Before — tableRow()
const color = highlight==='pass'
  ? '#34d399'
  : highlight==='fail'
  ? '#555'
  : 'inherit'; // ← SVG ignores inherit → black
✓ After — tableRow()
const color = highlight==='pass'
  ? '#34d399'
  : highlight==='fail'
  ? '#555'
  : '#c4c4e0'; // ← explicit light color
Outcome
✅ Fixed. All SVG table rows now use explicit hex color.
Lesson Learned
SVG ignores CSS color inheritance. Never use fill:inherit or color:inherit in SVG text elements. Always specify explicit hex values. SVG renders in its own context — CSS cascade does not apply the same way as HTML.

BUG-12
Wrong answer handling — Chicha re-asks same question without re-explaining ⚠️ Partial Fix AI / Prompt
When a student answers wrong twice on Easy difficulty, Chicha should re-explain with a new analogy. Instead she kept asking the exact same question repeatedly with no additional explanation.
▼
Root Cause
The system prompt marked wrong-answer handling as "mandatory" but the LLM treats all instructions as soft suggestions. When the model's training default (re-ask the question) conflicts with the prompt instruction (re-explain first), training wins. The model finds re-asking simpler and more natural than re-teaching.
Changes Made
✓ Fix — _wrongAttempts counter tied to prompt instruction
// _wrongAttempts tracked in code
Wrong answer → write exactly: [WRONG]
${diff.level === 'easy' && _wrongAttempts >= 2
  ? `Re-teach "${concept}" with a completely different analogy.
     Then ask a different easier question.`
  : `Explain what was wrong. Give a hint. Ask same question again.`}
Outcome
⚠️ Better but still LLM-dependent. The counter-based instruction is more specific than a general rule. Model follows it more consistently but not 100%.
Future Fix
Behavioural instructions to LLMs are unreliable. The structural fix is to handle this client-side: if wrong twice on Easy, send a separate system message override: "You must re-explain before asking again. This is not optional." Or better — trigger a specific re-teach API call that doesn't go through the normal lesson prompt at all.

BUG-14
Advancing to next concept — AI taught new concept without clearing history ✅ Fixed Learning Flow
After mastering "What is a Database" and clicking Continue, Chicha skipped teaching "What is a Table" and jumped straight to practice questions. Context from previous concept bled into the new one.
▼
Root Cause
advanceToNext() didn't clear _history. When the new concept's teaching prompt was sent, the AI saw 5 Q&A pairs about "What is a Database" in context. It assumed practice was still in progress and skipped teaching entirely, going straight to asking another question.
Changes Made
✗ Before — advanceToNext()
advanceToNext() {
  _currentSpark = getSparkForTopic(topic);
  _masteredThisSession = false;
  Chat.startSpark(); // history still had 5 Q&As
}
✓ After — advanceToNext()
advanceToNext() {
  _history = []; // ← clear history first
  _currentSpark = getSparkForTopic(topic);
  _masteredThisSession = false;
  _correctThisConcept = 0;
  Chat.startSpark(); // starts fresh
}
Outcome
✅ Fixed. History cleared on every concept advance. AI starts each concept with clean context.
Lesson Learned
LLM context is cumulative. Previous conversation history shapes every subsequent response. When moving to a new concept, the old context is actively harmful. Always clear _history at concept boundaries. Think of it as giving the AI a fresh sheet of paper for each new topic.
BUG-15
Free-text signal parsing — structural fragility of [CORRECT]/[WRONG] detection 🔴 Open AI / Prompt
The entire mastery system depends on scanning Chicha's free-text reply for "[CORRECT]" and "[WRONG]" tokens. This approach is inherently unreliable — the model sometimes includes them when it shouldn't, omits them when it should, or writes "CORRECT" without brackets.
▼
Root Cause
Fundamental architectural decision: using embedded tokens in free text as signals. Every bug related to premature mastery, missing face animations, concept skipping, and wrong answer handling traces back to this. The model is being asked to remember to include specific strings in specific positions in a free-form response — which conflicts with how language models generate text.
Current Workarounds Applied
Current approach — fragile
// Scan reply text for signal tokens
if (reply.includes('[CORRECT]')) { ... }
if (reply.includes('[WRONG]'))   { ... }
if (reply.includes('[AHA]'))     { ... }

// sanitiseReply strips unwanted "next topic" text
// Random position instruction fights (c) bias
// Two-mode prompt separates asking from evaluating
Proposed Fix (Phase 2)
✓ Structured JSON output — reliable
// System prompt asks for JSON response:
{
  "signal": "CORRECT" | "WRONG" | "AHA" | null,
  "message": "Chicha's response text here",
  "question": {  // only present when asking
    "text": "What is a primary key?",
    "options": [
      {"label":"a","text":"...","correct":false},
      {"label":"b","text":"...","correct":true},
      {"label":"c","text":"...","correct":false},
      {"label":"d","text":"...","correct":false}
    ]
  }
}

// Client reads signal from dedicated field:
const { signal, message, question } = JSON.parse(reply);
// No scanning. No ambiguity. 100% reliable.
Outcome
⚠️ Open — mitigated with workarounds but not fully solved. Structured JSON output is the definitive fix, planned for Phase 2.
Impact of This Bug
This single bug is the root cause of BUG-05, BUG-06, BUG-08, BUG-09, BUG-12, BUG-13. Six separate bugs all trace back to the same architectural decision. Fixing this one bug in Phase 2 will eliminate or significantly reduce all of them simultaneously. It is the highest-priority item in the entire backlog.
